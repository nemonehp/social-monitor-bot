# Аудит production-экспорта перед v1.3.0

Основа: экспорт `social-monitor-v1.2.4-export-20260719T224205Z.tar.gz`, фактический код production v1.2.3.

## Найдено в production

- 161 источник: 84 VK и 77 Telegram, интервал 120 секунд.
- 14 рабочих Telegram-сессий.
- Все 25 VK-учётных записей к моменту экспорта находились в `dead`; в логах были VK 1116 и явное `access_token expired` примерно через шесть часов.
- 7 рабочих прокси с различными внешними IP.
- VK-токен и прокси ранее выбирались независимо для каждой задачи, поэтому источник мог постоянно менять связку.
- Планировщик не оценивал суточную нагрузку до изменения интервала.
- Обнаружена попытка изменить frozen `CallbackQuery`, из-за чего падало изменение интервала.
- Незавершённая длинная VK-пагинация могла преждевременно записать новый watermark.
- Простое сравнение external_id не распознавало последний Telegram message ID внутри альбома.

## Модель для текущего пула

При 84 VK-источниках и интервале 120 секунд базовая оценка составляет 136 080 единиц API-нагрузки в сутки. При безопасном бюджете 30 000 единиц на VK-аккаунт требуется минимум 5 аккаунтов и 2 уникальных IP. Это расчёт внутренней консервативной модели, а не официальный лимит VK.

Для 77 Telegram-источников при том же интервале базовая оценка составляет 110 880 единиц в сутки. При безопасном бюджете 75 000 единиц требуется минимум 2 Telegram-сессии. Ограничение «3 аккаунта на IP» к Telegram не применяется.

## Реализованные защиты

- Атомарный суточный счётчик API-вызовов.
- Привязка VK-аккаунта к конкретному proxy ID и external IP.
- Максимум три VK-аккаунта на уникальный IP.
- Устойчивое распределение источников по аккаунтам.
- Временное снижение бюджета после rate-limit и автоматическое восстановление после окна штрафа.
- Остановка постановки задач только перегруженной платформы; checkpoint и очередь сохраняются.
- Сверка удалённого последнего ID с результатом, базой и committed watermark.
- Заморозка watermark/checkpoint при подозрении на пропуск.
- Известное истечение OAuth-токена переводит его в `dead` и освобождает proxy affinity.
- Отдельные форум-темы доставки и статистики.
