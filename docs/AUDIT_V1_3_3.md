# Аудит v1.3.3

## Найденная причина

`CredentialRepository.add` использовал уникальность `(platform, label)`, а `parse_vk_accounts` генерировал label из номера строки. Номер строки и пользовательское имя не являются идентичностью VK-аккаунта.

## Исправление

- Identity probe через `users.get` при каждом импорте.
- Канонический ключ: `VK + user_id`.
- Автоматический label `vk-<user_id>`.
- Upsert по подтверждённому account ID.
- Слияние известных дублей и API usage.
- Сохранение proxy affinity и runtime-счётчиков.
- Проверка несоответствия OAuth `user_id` реальному токену.
- Ошибки обрабатываются отдельно по каждой строке и не содержат секрет токена.

## Ограничение

Нельзя безопасно определить владельца уже мёртвого сырого токена, если в его OAuth-метаданных нет `user_id`. Такие legacy-записи не объединяются предположительно; они перестают влиять на новые импорты.
