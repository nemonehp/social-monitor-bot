# Production audit v1.2.3

Аудит выполнен по экспортированному состоянию production v1.2.2: исходникам, схеме PostgreSQL, обезличенным логам и диагностике последних материалов/доставок.

## Подтверждённые причины

1. **Повтор текста не был дублем базы.** Диагностика не обнаружила повторных `item_key` или повторных доставок. При одном медиа первые символы текста отправлялись в подписи, после чего полный текст уходил отдельным сообщением.
2. **Низкое качество Telegram-превью.** `PhotoStrippedSize` выбирался раньше нормальных размеров; это миниатюрный placeholder, а не финальное изображение.
3. **Повтор вложений VK-репоста.** Вложения внешнего поста и `copy_history` склеивались без канонической дедупликации.
4. **VK error 1116 повторялся как временный.** За 12 часов экспорт содержал около пяти тысяч повторных ошибок непригодного anonymous token вместо немедленного перевода токена в `dead`.
5. **Риск повтора при долгой доставке.** Lease доставки не продлевался во время сетевой отправки.
6. **Некорректный учёт попыток.** Захват пакета увеличивал `attempts` у всех сообщений источника, включая ещё не отправлявшиеся.

## Принятые решения

- Идемпотентность базы сохранена; destructive migration не требуется.
- Один длинный материал отправляется ровно один раз: либо целиком в подписи, либо медиа без подписи и один полный текст.
- Для Telegram используются реальные размеры и `video_cover`; stripped placeholder пропускается.
- Для VK и Telegram исходное изображение сначала берётся в лучшем доступном качестве, затем ограничивается локально.
- Полные видео не скачиваются.
- Добавлены heartbeat lease, поштучный `attempts`, секрет-redaction и окончательный статус для VK 1116.

## Осознанно оставленный архитектурный долг

Некоторые коллекторы и worker-функции остаются крупными. Их механическое дробление в hotfix увеличило бы риск регрессии без изменения поведения. Рекомендуется вынести разбор медиа, health policy и orchestration worker-ов в отдельные сервисы в следующем плановом рефакторинге, после фиксации v1.2.3 в production.
