# Design decisions

## PostgreSQL вместо отдельного брокера

Задачи сбора и доставки хранятся рядом с дедупликацией и состоянием источников. Захват выполняется через `FOR UPDATE SKIP LOCKED`, зависшие lease автоматически возвращаются в очередь.

Это уменьшает число обязательных компонентов и сохраняет возможность горизонтально добавить worker-процессы.

## Отдельные процессы, но не микросервисы

Все процессы используют один код, одну схему и одну базу. Разделение нужно для:

- независимого сетевого маршрута VK;
- изоляции Telethon-сессий;
- независимых рестартов доставки и планировщика.

## Мягкое удаление

Источники и прокси не удаляются физически сразу. Это сохраняет стабильные ключи, аудит и причины ошибок.

## Bootstrap без старого спама

Существующий контент фиксируется, но outbox не создаётся. Только после завершения bootstrap новые уникальные ключи создают delivery.

## Медиа не блокирует информацию

Основная запись события создаётся независимо от результата скачивания вложений. Медиа является расширением события, а не условием его существования.

## Пулы аккаунтов

- VK: один token одновременно занят одним slot.
- VK: один proxy одновременно занят одним slot.
- Telegram: одна StringSession — один последовательный worker loop.

Такой режим намеренно мягкий и рассчитан на 10–20 аккаунтов каждой платформы.
