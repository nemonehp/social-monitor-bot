# Production checklist

## До запуска

- [ ] Сервер физически находится вне РФ.
- [ ] `BOT_TOKEN` создан специально для проекта.
- [ ] `ADMIN_TELEGRAM_ID` — числовой ID владельца.
- [ ] PostgreSQL-пароль заменён.
- [ ] `APP_ENCRYPTION_KEY` сгенерирован и сохранён отдельно.
- [ ] Настроен ежедневный backup PostgreSQL.
- [ ] Добавлено минимум два независимых RU-прокси.
- [ ] Добавлены VK-токены.
- [ ] Добавлены Telegram StringSession.
- [ ] Сигнальный чат подключён и бот имеет право отправлять медиа.

## Проверка маршрутов

- [ ] `worker-tg` выходит напрямую с IP сервера вне РФ.
- [ ] `worker-vk` не способен выполнить VK-запрос без записи из таблицы `proxies`.
- [ ] Все активные прокси имеют `country_code=RU`.
- [ ] Глобальные `HTTP_PROXY`/`HTTPS_PROXY` не заданы для контейнеров bot и worker-tg.

## Функциональный smoke test

- [ ] Добавить одну тестовую ссылку Telegram.
- [ ] Добавить одну тестовую ссылку VK.
- [ ] Убедиться, что первая проверка не отправила старые посты.
- [ ] Опубликовать новый тестовый пост.
- [ ] Проверить сигнал, текст, регион и кнопку оригинала.
- [ ] Опубликовать альбом Telegram.
- [ ] Проверить, что он пришёл одним логическим событием.
- [ ] Закрепить старый пост VK и проверить отсутствие ложного нового сигнала.
- [ ] Опубликовать новый пост VK и сразу закрепить его.
- [ ] Проверить, что новый пост пришёл один раз.
- [ ] Временно отключить сигнальный чат и затем вернуть права.
- [ ] Проверить, что очередь доставки догналась.
- [ ] Отключить один прокси и проверить degraded/quarantine.

## Нагрузочная проверка

- [ ] Импортировать сначала 100 источников.
- [ ] Проверить равномерное заполнение `collection_jobs`.
- [ ] Проверить, что один Telegram-аккаунт выполняет только один job одновременно.
- [ ] Проверить, что один VK-токен и один прокси не используются двумя слотами одновременно.
- [ ] После этого импортировать основной пул.
