# Обновление до v1.3.3

## Причина

До этой версии VK-аккаунт идентифицировался по пользовательскому `label`. При импорте строк без label создавались порядковые имена `vk-1`, `vk-2` и так далее. Такой label не связан с владельцем токена, поэтому один аккаунт мог появляться несколько раз, а разные неизвестные аккаунты могли перезаписывать одну запись.

## Новая модель

1. Для каждого импортируемого токена бот вызывает `users.get` без `user_ids`, то есть получает текущего владельца токена.
2. Подтверждённый VK user ID сохраняется в `credentials.external_account_id` и `config_json.user_id`.
3. Системный label формируется как `vk-<ID>`.
4. Если этот ID уже существует, обновляются секрет токена, OAuth-метаданные и health-состояние существующей записи.
5. Proxy affinity, внутренний ID записи и накопленная статистика сохраняются.
6. Известные дубли с тем же user ID удаляются после переноса дневной API-статистики.

Старый ввод `label;token` продолжает разбираться, но первая часть игнорируется.

## Миграция

Миграция `0005_vk_account_identity` добавляет nullable-поле `external_account_id` и уникальность `(platform, external_account_id)`. Автоматически переносятся только однозначные `user_id`, уже сохранённые в OAuth-метаданных. Неизвестные мёртвые токены без подтверждённого ID не угадываются и остаются архивными строками.

## Проверка

После обновления импортируйте два разных токена одного VK-пользователя. Первый импорт должен добавить одну запись, второй — обновить её. В статусе число VK-аккаунтов не должно увеличиться.
