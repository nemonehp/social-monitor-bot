# Обновление до v1.3.4

Это точечный hotfix контроля полноты поверх v1.3.3.

## Причина

При первой подозрительной дыре создавался новый ORM-объект `IntegrityCheck`. Значение `default=0` применяется SQLAlchemy во время INSERT/flush, поэтому до flush Python-атрибут мог оставаться `None`. Операция `None += 1` откатывала транзакцию обработки VK-задачи.

## Исправление

- новый объект создаётся с `consecutive_gaps=0` явно;
- увеличение счётчика нормализует `None`, отрицательные и повреждённые значения;
- миграция обнуляет возможные legacy-NULL и подтверждает `NOT NULL DEFAULT 0`;
- очередь, публикации и checkpoint не очищаются.

## Запуск

```bash
CONFIRM_V1_3_4_UPGRADE=YES ./scripts/upgrade_v1_3_4.sh
```

Ожидаемая Alembic revision: `0006_integrity_counter_guard`.
